## 1. 背景与问题定义

平台现状是桌面优先的 web 应用（React 18 + TS + antd 5 / Express + PostgreSQL + Redis / Docker 沙箱判题）。学生端功能已经很完整：练习与测评、智能练习（每日推题/学习画像/知识点掌握）、积分/成就/商店/成长中心、错题本、排行榜、连胜。

问题在于：**这套"每天可练"的闭环依赖学生坐到电脑前**。手机浏览器打开桌面站点（表格、Monaco 编辑器、wangEditor）基本不可用，导致：

- 连胜机制形同虚设——当天没碰电脑就断；
- 每日推题（个性化推荐）没有消费场景，因材施教的价值打折；
- 《新的更新要求.txt》第 7 条"学生可以手机端（如小程序、网页）刷题，10 道题目，连胜机制"始终无法落地。

**本计划要解决的问题**：把"每天可练"装进口袋——小程序不是 web 的搬运，而是练习/打卡/激励闭环在碎片时间里的完整再造入口。教师与管理的复杂操作继续留在 web（见第 5 章范围裁剪）。

## 2. 目标与成功标准

| # | 目标 | 度量方式 |
|---|---|---|
| 1 | 学生全程手机完成"登录→今日推题 10 题→交卷→积分/连胜到账" | ≤5 分钟，全程零电脑依赖；E2E 用例验证 |
| 2 | 核心路径触达效率 | 首页今日任务卡→开始答题 1 次点击（与 5.1"3-2-1 到达"同口径：3 步=打开小程序→首页→进答题，其中点击 1 次）；冷启动 <3s；首屏可交互 <1.5s（中端安卓） |
| 3 | 碎片时间练习量真实上涨 | 上线 6 周内，作答提交中移动端占比 ≥30%。统计口径：分子=练习/测评整卷提交 + 智能推题单题作答（`source=mp`）；分母=双端全部作答提交（web+mp，同口径） |
| 4 | 工程质量 | 主包 <1.5MB；6 条主流程 E2E 全绿；提审一次通过（或仅资质补件一次） |

## 4. 技术选型（已定）

**微信原生小程序 + TypeScript + Vant Weapp。**

说明：用户指定"Vant 4 开源项目"，但 Vant 4 本体是 Vue3 web 库，无法运行在小程序环境；Vant 的官方小程序发行版是 **Vant Weapp**（有赞开源，原生 WXML 组件库）。因此：

- 选 **微信原生**（非 Taro/uni-app）：与 Vant Weapp 官方支持组合最稳、无编译层、调试直接；
- 失去与 React web 端的组件复用，通过 **共享 TS 类型包 + API 契约** 弥补（第 7.4 节）；
- 渲染层保持默认 WebView（Vant Weapp 对 Skyline 兼容有限，不冒险）。

其它候选（Taro3+React 复用面更广 / uni-app+Vue3 跨端更强）在需求简报中已对比，因 Vant 指定而落选。

**架构不变**：小程序 → (HTTPS) → nginx → backend(Express REST) → judge-service(Docker 沙箱) + Redis 队列。后端只做增量改造（第 8 章），不动存量业务逻辑。

## 5. 功能分类与信息架构（★重点）

### 5.1 小屏设计原则（所有页面遵守）

1. **一屏一事**：每页只承载一个主任务；次要功能收进宫格或"更多"，不做桌面式的全功能堆砌。
2. **拇指优先**：主操作固定在底部安全区（交卷/提交用 `van-submit-bar` 式底栏），热区 ≥44px。
3. **3-2-1 到达**：打开小程序 → 首页今日任务卡 → 点"开始"，3 步内进入答题（对应目标 2 的 1 次点击口径）。
4. **状态外显**：连胜/进度/积分在首页与答题页常驻可见，让激励资产随时被看见。
5. **弱网可用**：骨架屏（`van-skeleton`）+ 失败重试 + 答题草稿本地缓存（`wx.setStorage`），断网不丢作答；交卷请求携带幂等键，超时重试不产生重复计分/积分（机制见第 8 章）。

### 5.2 Tab 结构（4 Tab，微信规范 2-5 个）

```
tabBar
├── 首页    今日任务（每日推题/进行中练习）+ 连胜 + 积分速览 + 通知
├── 练习    练习/测评/报名 列表与作答入口
├── 成长    学习画像 + 宫格：积分·成就·商店·排行·错题本·统计
└── 我的    账号信息、报名记录、证书、通知中心、设置
```

分类逻辑：**"现在该做什么"在首页，"所有可做的"在练习，"做得怎么样/得到什么"在成长，"账号与凭证"在我的。** 教师 web 端的题库/组卷/审核/评卷/数据分析全部不进小程序；管理员不占 tabBar，在「我的」页出现「管理入口」进管理分包（5.6），自定义 tabBar 按角色切换列为后续增强。

### 5.5 明确裁剪项（防范围蔓延）

- 教师端 6 大模块（题库/活动组卷/审核工作台/评卷/数据分析/教学班）——web 独占；
- 管理端 9 类角色操作——web 独占；
- 注册审核流程——小程序内只做"查看报名/审核状态"提示，注册申请仍在 web；
- 编程题**只读期**不做部分交卷：活动含编程题时，答题页明示"编程题请在电脑端完成"，其余题正常提交（成绩按现有判分逻辑，不新增部分提交语义）。

### 5.6 管理端页面（2026-10-05 新增，轻量子集）

管理员复用同一小程序，从「我的」页进入管理分包（`packages/admin`），只做小屏适合的"随时看 + 快速批"：

| 页面 | 路径 | 核心内容 | 主要依赖接口 |
|---|---|---|---|
| 管理总览 | packages/admin/pages/home | 指标卡（学生数/测评数/本月测评/活跃教师）+ 最近测评列表 + 审批待办入口 | `GET /api/admin/dashboard/stats`（现有，已核实响应字段） |
| 审批中心 | packages/admin/pages/approvals | 注册审批列表（按状态筛选）+ 通过/驳回（单步操作，最适合手机） | `GET /api/registration/admin/requests`、`POST .../:id/approve|reject`（现有，已核实） |
| 用户查询 | packages/admin/pages/users（M3 视进度裁剪） | 按姓名/账号搜索，只读基本信息 | `GET /api/users/students|teachers`（现有） |

裁剪：题目编辑、组卷、测评管理、权限配置、成就配置等复杂 CRUD 一律不做——手机只做"快速批"和"随时看"，重操作回 web。**后端零新增**（管理端与家长端均复用现有接口）。

## 6. 关键交互与效果设计（★重点）

### 6.1 七种题型的小屏作答方案

| 题型 | 小屏方案 | 效果要点 |
|---|---|---|
| 单选 | 选项整行大卡片点选，选中态高亮+对勾 | 一屏一题为主，长题干折叠展开 |
| 多选 | 同单选 + 底部"确认本题"按钮防误触 | 选中顺序不敏感，提交前可改 |
| 判断 | 左右两大按钮（√ / ×）固定底部 | 全页面最快题型，单手 0.5s 作答 |
| 填空 | 原生键盘（按空类型切数字/文本），多空逐个定位跳转 | 自动聚焦下一空，减少点击 |
| 匹配 | 点左项→点右项配对，已配对显示同色标签；**不做拖拽** | 小屏拖拽误触率高，点选更稳 |
| 问答 | 多行 textarea + 字数统计 | 提交前过内容安全检测（第 8 章） |
| 编程 | 只读卡：题干/代码模板/样例/最近判题结果 + "去电脑端完成"引导 | 见 6.3，移动提交为下迭代候选 |

### 6.2 激励闭环的效果落地（"功能的效果"核心）

已建成的后端能力（连胜、成就触发、积分、每日推题、排行榜）在小程序上按"即时反馈"重新编排：

1. **单题流即答即判**：智能练习答完立即判对错（推荐作答接口已支持）——答对：绿勾 + 积分飘字 + 连对 combo；答错：红叉 + "看解析" + "加入错题本"两个快捷动作。把"做题→反馈"的延迟压到 1 秒内，这是 web 端整卷模式给不了的体验。
2. **连胜可视 + 保住提醒**：首页 7 日格条，当天格高亮"未打卡"；20:00 仍未打卡且用户订阅过 → 订阅消息"今天的连胜还差 1 题"。注意微信**一次性订阅消息"点一次只能发一条"**：在每次交卷完成页、推题完成页顺势调用 `wx.requestSubscribeMessage` 攒配额（配额策略见第 8 章），否则提醒上线几天就会断供。连胜是第 7 条需求的魂，必须同时有"看得见"（首页）和"丢不起"（提醒）两层。
3. **完成庆祝页**：每日推题 10 题完成 → 专门的完成页（连胜 +1、今日积分、能力值变化），并引导"分享战绩"——打卡心智在这里建立。
4. **成就半屏弹窗**：后端成就触发机制已有，解锁时以 `van-popup` 半屏动画弹出，不打断作答流。
5. **结果页 → 错题 → 再练**：解析页每个错题带"重练这题"，直接拼装一道智能推荐题——把"考完即止"变成"考完即学"的循环。

### 6.3 编程题（OJ 特色，本期只读，移动提交为下迭代）

- **只读期（本期 12 周窗口内）**：题干、代码模板、样例输入输出、该题最近一次判题结果（通过/不通过/得分）均可看；含编程题的活动在列表打"需电脑"标签，点进后给出明确引导。理由：原始需求（《新的更新要求》第 7 条）是"10 道题+连胜"的快刷闭环，编程题移动编辑器不在其中；Monaco 不可用，手机写代码强行做会同时伤害体验和工期。
- **提交期（下迭代候选，不在本期排期）**：全屏编辑器页——等宽字体 textarea + 缩进辅助键（Tab/花括号/引号自动补全关闭）+ 语言选择（复用题面 `supported_languages`）+ 模板一键注入；提交走现有 `/api/judge` → judge-service，结果页轮询判题状态（轮询需处理切后台/锁屏：`onShow` 恢复、`onHide` 暂停）。判题链路零改动，只新增前端编辑器。是否立项看本期上线后的编程题作答数据。

### 6.4 富文本与媒体（题干渲染）

- 后端已用 sanitize-html 白名单消毒入库；小程序端用 `mini-html-parser2` 一类方案把 HTML 转为 `rich-text` 节点渲染，白名单对齐后端（含 base64 截图降级为占位）。
- 图片：`van-image` 懒加载 + 固定宽高占位（防布局跳动）；图片域名必须加入小程序 downloadFile 白名单。
- 代码块：等宽字体 + 灰底样式，本期只读不高亮（highlights 包体不值）。

### 6.5 性能预算

| 项 | 预算 | 手段 |
|---|---|---|
| 主包 | <1.5MB | 主包只放 4 个 tab 页+登录；practice/smart/growth/parent 各独立分包（归属见 5.3） |
| 首屏可交互 | <1.5s（中端安卓） | `GET /api/mp/home` 一次聚合（避免 5 个串行请求）；骨架屏；关键数据本地缓存（离线可见上次连胜/任务） |
| 长列表 | 不卡顿 | `onReachBottom` 分页 + van-cell 简洁项 |
| 图片 | 不阻塞 | 懒加载 + CDN 域名白名单 |

## 7. 前端工程方案

### 7.1 技术栈

微信原生（WebView 渲染）+ TypeScript + Vant Weapp（npm 构建 `packNpm`）+ `mini-html-parser2`。不引 Redux 类重状态库：页面级状态 + 全局仅"用户信息/待同步草稿"两个 store。

### 7.2 目录结构

```
miniprogram/
├── app.ts / app.json          # tab 注册、分包、主题 CSS 变量
├── theme.wxss                 # 主题令牌（从 web 端 CSS 变量提取，主色/强调色对齐）
├── pages/                     # 主包：login + 4 个 tab 页（home/practice/growth/profile）
├── packages/practice/         # 分包：答题 answer / 结果 result
├── packages/smart/            # 分包：智能练习单题流 flow
├── packages/growth/           # 分包：points / achievements / ranking / wrong-questions / statistics 等
├── packages/parent/           # 分包：家长看板（P1）
├── components/                # 题型作答器 question-renderer（按 type 分发，第 6.1 表的直接实现）
├── services/                  # API 封装（wx.request 统一拦截：JWT 注入/401 刷新/错误 toast/幂等键）
├── types/                     # 题目/活动/结果类型——从 frontend/src/types 抽出共享（见 7.4）
└── utils/                     # storage 草稿、format、埋点
```

### 7.3 主题

从现有 web 端 CSS 变量提取令牌生成 `theme.wxss`（主色、强调色沿用学生端现有蓝灰体系如 #52708f 一族的既定值），Vant Weapp 通过 CSS 变量覆盖主题，保证双端视觉同源。

### 7.4 与 web 端的代码复用策略

- `frontend/src/types/*`（Question/Activity/Result 等）抽到共享包（npm file: 引入或复制脚本同步），**类型即契约**；
- 不共享组件（渲染层不同），共享枚举、常量与接口路径；
- 后端接口若因聚合接口而变更，只动 `services/` 一层。

## 8. 后端改造清单（全部增量，不动存量逻辑）

| 模块 | 内容 | 说明 |
|---|---|---|
| 鉴权 | `POST /api/auth/wechat`、`POST /api/auth/wechat/bind` | code2session 换 openid → 已绑定直接签发**现有 JWT**（复用 utils/jwt.js 的 7d/30d 双令牌与 tokenVersion）；未绑定返回 bindTicket，凭账号密码校验 users 表后写绑定。新表 `user_wechat_bindings(user_id, openid, unionid, created_at)`，user_id 即统一后的 users.id。**多设备口径**：小程序与 web 会话独立并存（白天 web 做测评、晚上小程序刷题互不影响），tokenVersion 仅在改密/封禁时递增——现有递增时机在 /bohe-plan 核实，若现状是登录即递增则需调整为改密/封禁递增。**绑定约束**：一个微信号绑定一个 user（openid 唯一索引），一个 user 同期只绑一个微信号，换绑走"我的-设置"先解绑再绑。**无手机号存量账号降级**：绑定页支持"用户名+密码"方式（与 web 登录等价校验），绑定成功后引导补录手机号 |

## 9. 合规与发布（2026-10-05 决策：延后至提审前完成，不阻塞开发）

> **执行口径**：开发期使用开发者工具「不校验合法域名」+ 体验版（限体验成员）分发验证；正式提审前必须补齐本章全部清单（主体、类目、ICP 备案、隐私指引、msgSecCheck）。发布时间受合规制约，开发节奏不受。

依据微信开放社区《小程序开放的服务类目》《非个人主体开放类目资质标准》（来源见文末）：

1. **主体**：教育类目不接受个人主体。可用主体：企业（营业执照）/ 公立学校（《事业单位法人证书》）/ 民办非企业单位。**这是全计划最大的前置不确定项，本周必须钉死（见需求简报"作业"）。**
2. **类目**：建议"教育服务-素质教育（非学科，含编程）"。非学科类培训机构通常需提供资质"4 选 1"（如《民办学校办学许可证》或教育部门审核登记等）；公立学校主体走《事业单位法人证书》路径。
3. **ICP 备案**：小程序自 2023-09 起强制备案；线上教育服务同时要求服务器域名 ICP 备案，且**备案主体名称须与小程序主体一致**（不一致需关联证明）。
4. **交易边界**：积分商店为虚拟积分兑换、无现金交易，不触发微信支付与虚拟支付相关资质；未来若卖课，需 ICP 经营许可证（企业主体、注册资本 100 万+），本期不做。
5. **隐私与未成年人**：配置《用户隐私保护指引》，声明收集手机号（登录）；学生多为未成年人，涉及不满 14 周岁儿童个人信息的，按儿童隐私政策单独同意；小程序端**不启用**身份证登录（现有 web 支持身份证方式），最小化收集敏感信息。
6. **内容安全**：UGC（问答题、纠错）接 msgSecCheck（第 8 章），提审前自测。
7. **审核周期**：资质齐全时类目审核约 3 个工作日，但整体提审预留 1-2 周缓冲（含一次被拒整改）。
